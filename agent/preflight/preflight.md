# Preflight — cloud vs local verification

BacksterOS Agent is a **web UI + Bun sidecar** with an optional **Tauri desktop shell**. Most product logic is cloud-verifiable; desktop-only behavior needs a local session.

## Decision rule

**Cloud-verifiable (default):**

- Sidecar unit tests: `cd sidecar && bun test`
- Web build: `npm run build:web`
- Deploy smoke: `npm run smoke:web` (healthz + static `index.html` from sidecar)
- Pure logic in `src/lib/**` with tests
- Server routes in `sidecar/src/**` (auth, Linear, sessions, static SPA)

**Local-only:**

- Tauri window chrome, traffic lights, global shortcut
- Embedded sidecar lifecycle in production `.app` (unless `BACKSTER_SERVER_URL` remote mode)
- PTY terminal (`src/editor/XTermView.tsx`)
- Native notifications when app backgrounded
- Full end-to-end with real OAuth popups and desktop file pickers

If a task mixes both: verify server/web in cloud; hand off desktop checks to a human or local agent.

## Fast repo signals

1. `src-tauri/**` → usually local-only runtime (Rust shell, PTY, hotkeys)
2. `sidecar/**` → canonical server source (cloud-safe; also copied into Tauri at build time)
3. `src-tauri/resources/sidecar/**` → **gitignored**; generated by `npm run build:sidecar`
4. `@tauri-apps/api` or `src/platform/**` with Tauri branches → local unless guarded for browser dev

## Suggested cloud commands

```bash
cd sidecar && bun test
npm run ci
```

`npm run ci` runs sidecar tests, `build:web`, and `smoke:web`.

## Credentials

If Linear/Calendar/Whoop need live credentials not available in cloud:

- Run tests and smoke without those integrations
- Note what was skipped in the Linear comment or PR
- Use label **`local`** when desktop verification is required

## Product mode

Default **`PRODUCT_MODE=linear`**: no vault folder required; agent cwd is server workspace dir. **`full`** restores vault nav and Obsidian settings.
